# SPEC-018: Temporal Atom Identity and Proof Lift via Synthetic Bridging

## 1. Executive Summary

### The Bug

`AtomKey` in `index.rs` excludes temporal bounds from atom identity. This causes `p[1,10]` and `p[20,30]` to collapse to the same `LitId`, producing three categories of incorrect behaviour:

1. **Body counter corruption** — Two temporal facts for the same predicate double-decrement a rule's body counter, causing premature firing.
2. **Cross-window satisfaction** — A rule requiring `p[20,30]` fires when only `p[1,10]` exists.
3. **Conclusion conflation** — Query operators cannot distinguish temporal windows in results.

See BUG-001 for full details and reproduction steps.

### Why the Branch Failed

The `fix/temporal-atom-identity` branch (33 commits) correctly added temporal to `AtomKey` but then implemented a **temporal proof lift** mechanism *inside* the defeasible reasoner. This lift — where proving `p[1,10]` also proves the base `p` — interacted non-trivially with SDL ambiguity blocking, retraction cascades, self-defeating cycle detection, and query operators. The mechanism required 13+ modifications to `defeasible.rs`, doubled its size (913 → 2,003 lines), and exhibited three circular fixing patterns (see BUG-001 §Branch Health Assessment).

### The Simpler Alternative

Instead of modifying the SDL algorithm, this spec defines temporal subsumption as a **pipeline stage** that generates explicit synthetic bridging rules *before* reasoning. Given a temporal fact `>> p[1,10]`, the pipeline generates a strict rule `p[1,10] -> p` that feeds into the standard SDL algorithm with zero modifications. The bridging stage is enabled by default for backward compatibility. This eliminates all interactions with the SDL cascade and keeps `defeasible.rs` unchanged.

## 2. Formal Definitions

These definitions extend DEFEASIBLE-LOGIC-SEMANTICS.md.

### Definition 1: Temporal Atom

A **temporal atom** is a literal `q` whose `temporal` field satisfies `q.temporal ≠ Temporal::empty()` (i.e., it has finite bounds, not the default `[-inf, +inf]`).

### Definition 2: Base Atom

The **base atom** `base(q)` of a temporal atom `q[s,e]` is the literal with the same functor, arguments, mode, and negation as `q`, but with `temporal = Temporal::empty()`. For a non-temporal atom, `base(q) = q`.

### Definition 3: Temporal Atom Identity

Two literals `p` and `q` are **temporally identical** if and only if:

```
p.functor = q.functor ∧
p.negation = q.negation ∧
p.mode = q.mode ∧
p.args = q.args ∧
p.temporal = q.temporal
```

This is the identity used by `AtomKey` for interning. It ensures that `p[1,10]` and `p[20,30]` produce distinct `AtomId` and `LitId` values.

### Definition 4: Temporal Subsumption

A temporal atom `q[s,e]` **temporally subsumes** its base atom `base(q)`. Formally: the truth of `q[s,e]` implies the truth of `q` (without temporal qualification) for the purpose of rule body satisfaction. This subsumption is made explicit through bridging rules rather than being implicit in the reasoner.

### Definition 5: Synthetic Bridging Rule

Given a temporal atom `q[s,e]` that appears as a fact head or rule head in the theory, the **synthetic bridging rule** for `q[s,e]` is the strict rule:

```
q[s,e] → base(q)
```

This rule is generated by the `TemporalBridge` pipeline stage and has a deterministic label `__bridge::<canonical_name>` where `<canonical_name>` is the SPL rendering of `q[s,e]`.

Bridging rules are **strict** (not defeasible) because temporal subsumption is a semantic entailment, not a default. They participate in Phase 1 (definite closure) of the SDL algorithm.

### Definition 6: Negation Bridging

For each positive bridging rule `q[s,e] → base(q)`, an **independent** negation bridging rule is generated:

```
~q[s,e] → ~base(q)
```

This is justified because if `~q` holds during `[s,e]`, then there exists evidence against `q` in general. The negation bridge enables defeater interactions to propagate correctly through temporal windows.

> **Note:** Negation bridging is conservative — it generates an attacker for `base(q)` whenever any temporal window produces `~q`. This is the correct behaviour for skeptical reasoning (SDL ambiguity blocking): if there is *any* evidence against `q`, the base conclusion should be blocked, not just the temporal variant.

## 3. Requirements

### REQ-001: Temporal Bounds in AtomKey

**Statement:** `AtomKey` must include temporal bounds (`Temporal`) as part of atom identity. Two literals that differ only in their temporal bounds must produce distinct `AtomId` and `LitId` values.

**Rationale:** This is the core fix for BUG-001. Without temporal in `AtomKey`, the indexer collapses distinct temporal atoms.

**Change to `index.rs`:**

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
struct AtomKey {
    functor: SymbolId,
    mode: (SymbolId, bool),
    args: Vec<Term>,
    temporal: Temporal,   // NEW: includes start and end TimePoint
}
```

**Invariant:** For any two literals `p` and `q`, `intern_literal(p) == intern_literal(q)` if and only if `p` and `q` are temporally identical (Definition 3).

**Trace:** TEST-001, TEST-002, TEST-PBT-001

### REQ-002: resolve_literal Preserves Temporal

**Statement:** `resolve_literal(lit_id)` must reconstruct the original temporal bounds from the `AtomKey`. The current implementation returns `Temporal::empty()` unconditionally; this must be changed to return `key.temporal.clone()`.

**Rationale:** Downstream consumers (query operators, conclusion emission, explain traces) rely on `resolve_literal` to reconstruct the original literal. Losing temporal bounds here causes silent data loss in query results.

**Change to `index.rs:resolve_literal`:**

```rust
Literal::from_ids(
    key.functor,
    lit_id.is_negated(),
    mode,
    key.temporal.clone(),   // was: Temporal::empty()
    key.args.clone(),
)
```

**Trace:** TEST-003, TEST-004

### REQ-003: Body Counter Correctness

**Statement:** After adding temporal to `AtomKey`, each distinct temporal variant of a predicate produces a distinct `LitId`. A rule with `p` (base) in its body has its counter decremented only when `p` (base) is proven, not when `p[1,10]` or `p[20,30]` are proven. The bridging rule `p[1,10] → p` causes `p` (base) to be proven via standard rule firing, which then decrements the counter exactly once.

**Invariant:** A rule's body counter is decremented at most once per distinct `LitId` in its body. No double-decrement is possible because distinct temporal variants have distinct `LitId` values.

**Trace:** TEST-005, TEST-006, TEST-PBT-001

### REQ-004: TemporalBridge Pipeline Stage

**Statement:** A new pipeline stage `TemporalBridge` shall be implemented as a `PipelineStage` that:

1. Scans all rule heads in the theory for temporal atoms (literals where `temporal ≠ Temporal::empty()`).
2. For each such temporal head literal `q[s,e]`, generates a strict bridging rule `q[s,e] → base(q)` with label `__bridge::<q[s,e].to_spl()>`.
3. For each positive bridging rule, generates a corresponding negation bridge `~q[s,e] → ~base(q)` with label `__bridge::neg::<q[s,e].to_spl()>`.
4. Adds all generated bridging rules to the theory.
5. Does NOT generate a bridge if `base(q)` already appears as a head literal in the theory (demand-driven: only bridge when there is a semantic gap).

**Insertion point:** After grounding, before indexing. In `prepare()`, the bridge stage is inserted between the `Ground` stage and the `TemporalVarValidation` stage:

```
Validate → WildcardRewrite → Ground → TemporalBridge → TemporalVarValidation → [TemporalFilter]
```

**Default:** The stage is **enabled by default** in both `prepare()` and `Pipeline::default_pipeline()`.

**Trace:** TEST-007, TEST-008, TEST-009, TEST-010

### REQ-005: Bridge Rules Participate in SDL Normally

**Statement:** Synthetic bridging rules are **strict rules** and participate in Phase 1 (definite closure) of the SDL algorithm. They require no special treatment — the existing `resolve_definite` function processes them as ordinary strict rules with a single body literal.

**Invariant:** The defeasible reasoning module (`reason/defeasible.rs`) requires **zero modifications**. All temporal subsumption is handled before reasoning begins.

**Trace:** TEST-011, TEST-012

### REQ-006: Negation Complement with Temporal Identity

**Statement:** `LitId::complement()` (which flips the negation bit) continues to work correctly with temporal identity. For a temporal atom `q[s,e]`, `complement(lit_id(q[s,e])) = lit_id(~q[s,e])` — the complement shares the same temporal bounds. This is already the case because `AtomId` is shared between positive and negative forms.

**Invariant:** For any `LitId` l, `l.complement().complement() == l`. Adding temporal to `AtomKey` does not affect this property because temporal is part of the `AtomId`, not the negation bit.

**Trace:** TEST-013

### REQ-007: Query Temporal Wildcard Matching

**Statement:** Query operators (`query`, `what_if`, `why_not`, `abduce`) must support temporal wildcard matching: when the query literal has `temporal = Temporal::empty()`, it matches conclusions with any temporal bounds (including non-temporal conclusions). When the query literal has specific temporal bounds, it matches only conclusions with identical temporal bounds.

**Matching function:**

```rust
fn matches_query(query: &Literal, conclusion: &Literal) -> bool {
    query.name_id() == conclusion.name_id()
        && query.negation == conclusion.negation
        && query.mode == conclusion.mode
        && query.predicate_args() == conclusion.predicate_args()
        && (query.temporal.is_empty() || query.temporal == conclusion.temporal)
}
```

**Rationale:** Users querying `p` (without temporal) expect to see all temporal variants of `p` in the results. Users querying `p[1,10]` expect only that specific window. This is the natural wildcard semantics.

**Note:** This matching is used ONLY in query operators, NOT in rule body satisfaction (which uses exact `LitId` equality via the index).

**Trace:** TEST-014, TEST-015, TEST-016

### REQ-008: Backward Compatibility for Non-Temporal Theories

**Statement:** Theories with no temporal atoms must produce identical reasoning results before and after this change. The `TemporalBridge` stage is a no-op when no temporal heads are found (it generates zero rules and returns the theory unchanged).

**Invariant:** For any theory `T` where no literal has `temporal ≠ Temporal::empty()`:
- `TemporalBridge::apply(T) = T` (no rules added)
- `IndexedTheory::build(T)` produces identical `AtomId`/`LitId` mappings (because `AtomKey` now includes `temporal = Temporal::empty()` for all literals, which is the same value for all, so the mapping is isomorphic)

**Trace:** TEST-017, TEST-PBT-002

### REQ-009: Conclusion Temporal Preservation

**Statement:** Conclusions emitted by the reasoning engine must preserve the temporal bounds of the proven literal. Specifically:

- If `+d q[1,10]` is proven, the `Conclusion.literal` must have `temporal = Temporal::new(1, 10)`.
- If `+d q` (base) is proven via a bridging rule from `q[1,10]`, the `Conclusion.literal` must have `temporal = Temporal::empty()` (the base literal's temporal).

This is automatically satisfied by REQ-002 (`resolve_literal` preserves temporal).

**Trace:** TEST-003, TEST-004

### REQ-010: Bridge Label Determinism

**Statement:** Bridging rule labels must be deterministic and collision-free. The label format is:

- Positive bridge: `__bridge::<to_spl()>` where `to_spl()` is the SPL rendering of the temporal head literal.
- Negation bridge: `__bridge::neg::<to_spl()>` where `to_spl()` is the SPL rendering of the temporal head literal (positive form).

**Invariant:** Two distinct temporal literals always produce distinct SPL renderings (because SPL rendering includes temporal bounds), so bridge labels are unique.

**Trace:** TEST-018

## 4. Architecture Decisions

### ADR-001: Synthetic Bridging vs Implicit Lift

**Context:** When temporal is added to `AtomKey`, non-temporal rules (e.g., `p => q`) cannot see temporal facts (e.g., `>> p[1,10]`) because they have different `LitId` values. Two approaches were considered:

1. **Implicit lift** (branch approach): Modify `defeasible.rs` so that proving `p[s,e]` also proves `base(p)` via an internal mechanism.
2. **Synthetic bridging** (this spec): Generate explicit strict rules `p[s,e] → base(p)` before reasoning.

**Decision:** Synthetic bridging.

**Rationale:**

| Criterion | Implicit Lift | Synthetic Bridging |
|---|---|---|
| SDL modifications | 13+ modifications, file doubled | Zero modifications |
| Code complexity | 1,100+ new lines in defeasible.rs | ~100 lines in new pipeline stage |
| SDL soundness | Requires separate proof (not provided) | Preserved by construction (standard rules) |
| Retraction cascades | 9 modifications, circular fixes | Not applicable (strict rules don't retract) |
| Self-defeating cycles | 5 iterations of detection logic | Impossible (strict rules can't self-defeat) |
| Query operator changes | matches_query three-level system | Single-level wildcard (REQ-007) |
| Testability | Hard to unit-test internal mechanism | Standard pipeline stage testing |

**Trade-offs:**

- Bridging rules increase theory size by at most `2 * |temporal heads|` rules. This is negligible for practical theories.
- Bridging rules are strict, so they participate in definite closure (Phase 1). This means temporal subsumption is unconditional — if `p[1,10]` is a fact, `p` (base) is definitively proven. This is the correct semantics: a temporal fact is stronger evidence than a defeasible default.
- If a theory has `>> p[1,10]` and `>> ~p[20,30]`, the bridges produce both `p` (base, definite) and `~p` (base, definite). This creates a definite contradiction, which is the correct outcome — the theory is inconsistent at the base level.

**Rejected alternative:** The implicit lift approach was rejected because the branch demonstrated that it creates cascading interactions with SDL internals that are difficult to reason about and test.

### ADR-002: Full Temporal in AtomKey vs Hash/Canonical

**Context:** Two representations for temporal identity in `AtomKey` were considered:

1. **Full `Temporal`** — store the `Temporal` struct (two `TimePoint` values) directly in `AtomKey`.
2. **Hash/canonical** — store a hash or canonical string of the temporal bounds, avoiding the `Temporal` struct dependency.

**Decision:** Full `Temporal` in `AtomKey`.

**Rationale:**

- `Temporal` already implements `Eq` and `Hash` (via `TimePoint`'s implementations).
- Storing the full value allows `resolve_literal` to reconstruct the temporal bounds without an auxiliary lookup table.
- Hash collisions with a digest approach would silently re-introduce the identity collapse bug.
- The memory overhead is 16 bytes per `AtomKey` entry (two `TimePoint` values, each an enum discriminant + i64).

### ADR-003: Demand-Driven Bridge Generation Scope

**Context:** The bridge stage could generate bridges for:

1. **All temporal atoms** — every temporal literal in the theory gets a bridge.
2. **Demand-driven** — only temporal atoms that appear as heads (facts, rule conclusions) get bridges, and only when `base(q)` does not already appear as a head.

**Decision:** Demand-driven generation, bridging only temporal head literals.

**Rationale:**

- Body literals don't need bridges — they are matched exactly via `LitId` during rule body satisfaction.
- If `base(q)` already appears as a head, the theory already has a direct path to proving `base(q)` — no bridge needed.
- This minimises the number of synthetic rules added to the theory.

**Note:** "Head literal" includes fact heads (`>> p[1,10]`), strict rule heads, defeasible rule heads, and defeater heads. All of these can produce conclusions that need bridging.

### ADR-004: Independent Negation Bridge Policy

**Context:** Three policies for negation bridging were considered:

1. **No negation bridges** — only positive subsumption.
2. **Coupled negation** — `~q[s,e] → ~base(q)`, generated for every positive bridge.
3. **Independent negation** — negation bridges generated independently based on whether `~q[s,e]` appears as a head.

**Decision:** Coupled negation (option 2).

**Rationale:**

- If `~q[s,e]` is derivable, it represents evidence against `q` during interval `[s,e]`. Under skeptical SDL semantics, this evidence should be visible at the base level to enable ambiguity blocking.
- Without negation bridges, a theory with `>> p[1,10]` and `~p[20,30]` would derive `+d p` (base) without any blocking, because the `~p[20,30]` evidence would be invisible at the base level. This is unsound under skeptical semantics.
- Coupled generation is simpler to implement and reason about than demand-driven negation analysis.

### ADR-005: No Change to Literal::PartialEq

**Context:** The `fix/temporal-atom-identity` branch modified `Literal::PartialEq` to include temporal, then partially reverted this change due to cascading failures.

**Decision:** `Literal::PartialEq` remains unchanged — it continues to exclude temporal bounds.

**Rationale:**

- `Literal::PartialEq` is used in many contexts (rule body matching, theory manipulation, test assertions) where temporal-agnostic equality is correct.
- Temporal identity is handled exclusively via `AtomKey`/`LitId` in the indexer, which is the single point of truth for reasoning identity.
- The branch demonstrated that changing `Literal::PartialEq` creates cascading failures across the codebase (see BUG-001 §Cycle 3).
- Query temporal matching uses the explicit `matches_query` function (REQ-007) rather than `PartialEq`.

## 5. Constraints

### CON-001: AtomKey Struct

```rust
/// Key used for interning atoms.
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
struct AtomKey {
    functor: SymbolId,
    mode: (SymbolId, bool),
    args: Vec<Term>,
    temporal: Temporal,
}
```

`Temporal` must implement `Eq` and `Hash`. Current implementation already satisfies this via `TimePoint`'s derived/manual `Eq` and `Hash`.

### CON-002: Pipeline Stage Interface

```rust
/// Synthetic bridging for temporal subsumption.
#[derive(Debug, Default)]
pub struct TemporalBridge;

impl PipelineStage for TemporalBridge {
    fn name(&self) -> &'static str { "temporal-bridge" }

    fn apply(&self, theory: Theory, ctx: &mut PipelineContext) -> Result<Theory> {
        // 1. Collect temporal head literals
        // 2. For each, generate strict bridge rule q[s,e] → base(q)
        // 3. Generate negation bridge ~q[s,e] → ~base(q)
        // 4. Add to theory
        // 5. Report count in ctx diagnostics
    }
}
```

### CON-003: Query Matching Function

```rust
/// Check if a query literal matches a conclusion literal.
///
/// Temporal wildcard: if query has empty temporal, matches any temporal.
/// Otherwise requires exact temporal match.
pub fn matches_query(query: &Literal, conclusion: &Literal) -> bool {
    query.name_id() == conclusion.name_id()
        && query.negation == conclusion.negation
        && query.mode == conclusion.mode
        && query.predicate_args() == conclusion.predicate_args()
        && (query.temporal.is_empty() || query.temporal == conclusion.temporal)
}
```

## 8. Termination and Soundness

### Termination

The `TemporalBridge` stage adds a bounded number of rules: at most `2 * |H_t|` where `|H_t|` is the number of distinct temporal head literals. Each bridging rule has exactly one body literal and one head literal. The stage iterates over the theory's rules once and does not recurse. It terminates in `O(|R|)` time where `|R|` is the number of rules.

The subsequent reasoning phases (definite closure, defeasible fixed-point) are unmodified and retain their existing termination guarantees from DEFEASIBLE-LOGIC-SEMANTICS.md.

### Soundness

**Claim:** The TemporalBridge stage preserves SDL soundness.

**Argument:**

1. Bridging rules are strict rules of the form `q[s,e] → base(q)`. By the semantics of strict rules in DEFEASIBLE-LOGIC-SEMANTICS.md §Strict Rules, if `+D q[s,e]` then `+D base(q)`.

2. This is sound because temporal subsumption is a semantic entailment: if `q` holds during `[s,e]`, then `q` holds (without temporal qualification). The temporal window is a strengthening, and removing it is weakening — which is valid for positive conclusions.

3. Negation bridges `~q[s,e] → ~base(q)` are sound under skeptical semantics: evidence against `q` during any window is evidence against `q` in general. This enables ambiguity blocking at the base level, which is the correct behaviour for SDL.

4. The SDL algorithm operates on the augmented theory (original rules + bridges) using its standard phases. Since the bridges are ordinary strict rules, all SDL properties (monotonicity of definite closure, well-foundedness of defeasible fixed-point, termination) are preserved.

5. No modifications to `defeasible.rs` means no new interactions with SDL internals. The fixed-point computation sees the same kinds of inputs (strict rules, defeasible rules, defeaters) it always has.

**Comparison with implicit lift:** The implicit lift approach could not provide this argument because the lift mechanism created new proof obligations *during* the fixed-point computation, potentially invalidating the well-foundedness assumption.
