## Findings

### P1 — #29: ordinary dependencies are missing from stratification

`crates/spindle-core/src/pipeline/stratify.rs:116–139` builds only direct fold
edges. A chain `raw → a → fold → b → c → fold → total` emits both `total(0)` and
`total(10)` for a sole input of 10. The ordinary `b → c` edge must propagate
the stratum requirement. A cycle `a → fold → b → a` is also accepted, despite
having no valid aggregate stratification. Both cases have executable probes.

Include ordinary dependencies in the graph with non-strict ordering and fold
dependencies with strict ordering. Later commit `9cff83a` addresses this area.

### P1 — #29: grounding reintroduces defeated aggregate inputs

`crates/spindle-core/src/reason/mod.rs:249–262` includes all lower-stratum rules
again. Grounding collects their candidate heads before conflict resolution, so
the fold can read a defeated candidate even though the preceding stratum already
rejected it. With `raw(10)`, opposing defeasible rules for `pay(10)`, and preference
for the negative rule, a sum emits both `total(0)` and `total(10)`.

Read finalized conclusions only; do not rerun lower-stratum candidate generation
into the fold's input relation. Later commit `df274ee` changes this model.

### P1 — #29: transported defeasible conclusions become strict facts

`crates/spindle-core/src/reason/mod.rs:181–205,243–247` discards conclusion type
when accumulating positive literals and reinserts every one with `Rule::fact`.
A defeasible derivation of `pay(10)` followed by a sum returns both `-D pay(10)`
and `+D pay(10)`. The latter is fabricated by transport across the boundary.

Preserve proof strength and reconcile conclusions across strata. Later commit
`c33b96c` addresses proof-strength transport; `df274ee` also changes accumulation.

### P1 — #29: CLI reasoning bypasses the stratified dispatch

`crates/spindle-core/src/pipeline/mod.rs:354–365` deliberately returns an unground
theory for multiple strata, but `crates/spindle-cli/src/cli/commands/reason.rs:44`
passes it directly to `reason_prepared`. The probe using exactly that call path
returns unbound negative conclusions and omits the total that `reason_with_options`
derives. A library-only integration test therefore does not protect CLI users.

Expose one prepared-result dispatcher and use it at the CLI boundary. Later
commit `ffcfb11` introduces `reason_from_prepared`. The actual WASM head calls
`reason` after `prepare`, so this review does not attribute the CLI bypass to
WASM merely because the later commit message mentions both interfaces.

### P2 — #29: arbitrary binary reducers violate order independence

`crates/spindle-core/src/pipeline/validate.rs:335–355` checks existence and arity
but accepts subtraction for `(fold ?s required - ?x (v ?x))`. A probe observed
`total(-7)` versus `total(7)` for the same facts 10 and 3 with differing input
order. Hash iteration can make this appear or disappear across processes.

Require a lawful reduction contract. The retained regression checks rejection
of subtraction instead of relying on a particular hash iteration order. Later
commit `bb3d773` adds a fold-safe flag, but a flag alone does not establish the
associativity of bounded or floating-point arithmetic.

### P2 — #27: float-to-integer overflow check accepts 2^63

`crates/spindle-core/src/builtins.rs:563–572` casts the float to `i64`, then checks
by casting back. At exactly 9223372036854775808.0 the integer cast saturates to
`i64::MAX`, which rounds back to that same float. The floor probe returns
9223372036854775807 instead of failing. Ceil uses the same faulty guard at
lines 615–624. Check the representable range before casting, with an exclusive
upper bound at 2^63.

### P2 — #26: extension calls remain numeric-only despite the Term interface

`crates/spindle-core/src/arith.rs:790–804` at #26 evaluates arguments through
`NumericValue` and converts every return value back to it, even for direct `bind`.
A registered zero-argument function returning the symbol `monday` produces no
`day(monday)` conclusion. Symbols cannot flow through the promised general
`Term` interface. This is an intentional limitation in the current tests
(`non_numeric_return_discards_path`), but it falls short of Skein's Phase 1
design, which requires binding a returned Term directly.

Separate general term evaluation from numeric arithmetic conversion, or explicitly
carry this as an unmet integration requirement. This is not a regression in
pre-existing numeric-only programs.

## Lean follow-up

The existing Lean work clarifies definite versus defeasible reasoning, but its
AST and evaluator do not contain aggregation or extension calls. Its proofs do
not validate this PR stack. Skein's Lean implementation supplies a useful
completed-stratum design, with a different defeasibility model.

At the user's request, work now starts from the
[Lean aggregation contract](../../lean/AGGREGATION.md). It establishes the initial
boundary laws and records the remaining evaluator and Rust-refinement obligations.
